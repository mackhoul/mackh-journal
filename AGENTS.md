# MackH Journal: правила работы

- Общайся по-русски, просто; объясняй результат и следующий шаг новичку.
- Claude Code — основной разработчик. Codex — независимый ревьюер. Не запускай другого агента автоматически: пользователь передаёт задачу между приложениями сам.
- Перед изменениями прочитай git status, текущую ветку и diff. Не перезаписывай чужую незавершённую работу.
- Для задач сайта сначала используй site-studio, если скилл доступен. Сохраняй направление DESIGN.md. Нет скилла — сообщи об этом. Для перевода DA/EN используй da-en-translate; для order flow — volume-orderflow.
- Работай небольшими задачами в отдельной ветке. Перед субагентами, параллельными сессиями или полной переделкой предупреди о расходе лимита; не запускай их без запроса.
- Не выполняй reset --hard, clean -fd, force push, удаление веток или автоматическое объединение несвязанных историй. Не переключай ветку при чужих незавершённых изменениях.
- Не отправляй изменения в main и не публикуй сайт без явного запроса. После ревью можно отправить рабочую ветку обычным push.
- Не добавляй .env, ключи, токены, данные журнала, резервные копии и личные настройки агентов в Git. Не проси пользователя присылать секреты.
- index.html — основное приложение; fonts/ — локальные шрифты; server.js — Express backend; DESIGN.md — дизайн. Не считай проект только статическим сайтом.
- Пользователь сообщает о хранении данных в Cloudflare. Backend также содержит интеграции Supabase, Stripe и Telegram; реальную схему хранения нужно проверить перед изменениями данных. Не трогай production-данные при локальной проверке.
- env.example и .env.example — шаблоны, не реальные секреты. Пока сохраняй оба, пока отдельная задача не устранит дублирование.
- Проверяй соразмерно изменению. Для серверного JS: node --check server.js. Для интерфейса: проверить изменённые сценарии, консоль, ширины 375/768/1440, клавиатуру. Не утверждай, что проверил то, чего не запускал.
- Перед коммитом проверь git diff --check, список файлов и отсутствие секретов. Добавляй файлы явно, не используй git add . без проверки.
- В отчёте: что изменено, что проверено, ограничения, ветка и коммит. Правки Claude проверяет Codex по diff, не только по отчёту Claude.

## Review guidelines

Codex сначала выполняет review без правок. Проверяет ошибки поведения, потерю данных, безопасность авторизации, расчёты сделок и P&L, время/даты, миграции localStorage, API и отсутствие секретов. Для проблемы указывает файл, строку, сценарий и серьёзность. Если находок нет, прямо сообщает это и отмечает непроверенные сценарии. Общие вкусовые замечания не выдаёт за баги.
