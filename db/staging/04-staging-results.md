# Результаты staging-проверки защиты удалений

Проект `mackh-journal-test` (ref `ibjjethbdgawqnttqmvc`), локальный сервер `http://127.0.0.1:3010` с кодом ветки `fix/trade-save-delete`. Интерфейс — временная копия `index.html` вне Git, где изменена только строка `const SERVER` (на `http://127.0.0.1:3010`), раздавалась с `127.0.0.1:8081`. Telegram, Stripe и R2 у сервера выключены. Production, `main` и Render не использовались. Исключение: при открытии оригинального `index.html` в предпросмотре ушёл один публичный `GET /config` к рабочему Render — без ключей и без изменений.

Тестовые аккаунты интерфейса: `a@example.com`, `b@example.com`. Их создал пользователь в панели Supabase тестового проекта. Пароли хранятся только в `.env.staging`, который игнорируется Git.

## 4. Находки вне этой ветки (отдельные задачи)

1. **Гонка первой связки веб-аккаунта.** При первом входе параллельные запросы создают разные `user_id`. `account_links` пишется со слиянием (`server.js:161`), поэтому побеждает последний, а ранний запрос успевает отработать со «своим» id. В журнале по два «linked new web account» для a@ и b@. Сирот (сделок или настроек под потерянным id) в этот раз нет. Риск: запись при первом входе уйдёт под потерянный id.
2. **Вторая вкладка не узнаёт об удалении из первой** до перезагрузки (A8): показывает сделку как обычную и пишет её в общий кэш.
3. **Доступ с клавиатуры** (A11): карточки сделок и «Отменить» не фокусируются.
4. **`created_at` означает «последнее сохранение»** (A2): после правки меняется порядок сделок с сервера.
5. **Дата новой сделки после полуночи** берётся вчерашняя (по UTC). Это известный пункт аудита.
6. `GET /ideas` → 404 в консоли: идеи пока только на устройстве. Шум, не ошибка.

## 5. Не проверено

- Render, Telegram-бот, загрузка и удаление картинок в R2 (только сохранность уже заданной `img_url`).
- Настоящий телефон и Telegram WebView (только эмуляция ширин в браузерной панели).
- Одновременная работа двух разных устройств (только две вкладки одного браузера).
- Падение процесса или компьютера посреди восстановления.
- Рабочее включение — только после отдельного решения пользователя.
