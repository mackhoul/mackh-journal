# Стратегии в аккаунте — как включить

Что даёт: раздел «Стратегии» хранит стратегии, их редакции, наблюдения, гипотезы
и итоги недели в аккаунте. Без этой миграции раздел работает, но всё остаётся
только на устройстве, а статус честно пишет: «Сервер пока не принимает стратегии».

Сначала прочитайте целиком. Порядок — сверху вниз.

## 0. Перед стартом

- Изменения ветки `feature/strategy-route` должны пройти ревью Codex.
- Миграцию сначала прогоняют на **тестовом** проекте Supabase (без настоящих
  сделок) и только потом, отдельным решением, — на рабочем.
- Миграция новая и ничего не меняет в таблице `trades`: она только добавляет
  таблицу `strategy_docs` и две функции.

## 1. Тестовый проект

1. Supabase (тестовый проект) → **SQL Editor** → **New query**.
2. Вставьте весь файл `db/migrations/2026-10-28-strategy-docs.sql` → **Run**.
   Ожидаемо: `Success. No rows returned`. Повторный запуск безопасен.
3. Проверка (там же):

   ```sql
   select public.mj_save_doc('check_1', 1, 'note', '{"text":"проверка"}'::jsonb, 1);
   select public.mj_save_doc('check_1', 1, 'note', '{"text":"проверка"}'::jsonb, 1);
   select public.mj_save_doc('check_1', 1, 'note', '{"text":"другой"}'::jsonb, 1);
   select public.mj_delete_doc('check_1', 1, 'note', 2);
   select public.mj_save_doc('check_1', 1, 'note', '{"text":"поздно"}'::jsonb, 3);
   delete from public.strategy_docs where id = 'check_1' and user_id = 1;
   ```

   Ожидаемо по порядку: `saved`, `same`, `collision`, `deleted`, `deleted`.
   `same` — повтор той же версии с тем же текстом (например, запрос ушёл
   дважды). Та же версия с другим текстом — `collision`: запись не меняется,
   приложение отправит документ ещё раз с новой версией.

## 2. Сервер

Новый `server.js` (маршруты `/strategy-docs`) работает и до миграции: отвечает
503, приложение хранит стратегии на устройстве и отправит их позже. После
миграции первый же запрос сохраняет их в аккаунт.

## 3. Рабочий проект — только отдельным решением

То же, что в шаге 1, после ревью и проверки на тестовом проекте. Сделки, их
защита от воскрешения и синхронизация этой миграцией не затрагиваются.

## Откат

В конце SQL-файла — закомментированный блок «Rollback». Он удаляет таблицу со
стратегиями **всех** аккаунтов: перед ним сделайте экспорт `strategy_docs` в CSV.
Сделки при откате не меняются; у сделок останутся ссылки на редакции, которых
больше нет, — окно сделки покажет «редакция ещё не загружена».
