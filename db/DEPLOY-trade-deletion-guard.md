# Защита удалённых сделок — как включить

Что даёт: если запрос на сохранение сделки пришёл на сервер позже, чем её
удаление (например, после долгого ожидания), удалённая сделка больше не
воскресает. База сама помнит удаление.

Порядок не важен: сервер работает и до миграции (по-старому), и после
(с защитой). Удобнее так:

## 1. Резервная копия (обязательно)

Supabase → проект → **Table Editor** → таблица `trades` → **Export → CSV**.
Сохраните файл у себя. На бесплатном тарифе автоматических копий может не быть.

## 2. Миграция базы

1. Supabase → **SQL Editor** → **New query**.
2. Вставьте весь файл `db/migrations/2026-10-21-trade-deletion-guard.sql`.
3. Нажмите **Run**. Должно быть `Success. No rows returned`.

Повторный запуск безопасен.

Проверка: в **Table Editor** → `trades` появилась колонка `deleted_at` (пустая).

## 3. Новый сервер

`server.js` попадает на Render, когда ветка будет слита в `main`
(после ревью, это ваше отдельное решение). Render перезапустится сам.

## 4. Проверка

Откройте `https://mackh-journal.onrender.com/health/db`.
Нужно увидеть `"deletion_guard": true`. Если `false` — миграция не применена
(сервер перепроверяет раз в 5 минут, подождите и обновите страницу).

## Что меняется для данных

- Удалённая сделка не стирается из таблицы целиком: остаётся строка-отметка
  с ID, владельцем и датой `deleted_at`. Содержимое (`data`) и ссылка на
  скриншот стираются. Сам файл скриншота в хранилище, как и раньше, не удаляется.
- Приложение такие строки не показывает.
- Старые версии приложения продолжают работать: попытка сохранить удалённую
  сделку получает ответ «ок, пропущено» и не создаёт её снова.

## Откат

В конце SQL-файла есть закомментированный блок «Rollback». Он удаляет функции,
строки-отметки и колонку. После отката перезапустите сервер на Render
(Manual Deploy → Restart), чтобы он сразу перешёл в старый режим.
