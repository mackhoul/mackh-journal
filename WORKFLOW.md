## Одна задача — один цикл

1. Открой эту папку в Claude Code (в привычном приложении Claude или доступной среде).
2. Попроси: «Прочитай CLAUDE.md и WORKFLOW.md. Проверь Git и создай отдельную ветку от актуальной согласованной версии. Сделай [одну конкретную задачу]. Проверь результат. Подготовь изменения для Codex, не публикуй main».
3. Дождись окончания работы Claude. Не запускай одновременно правки той же папки в Codex.
4. Открой эту же папку как проект в Codex. Попроси: «Прочитай AGENTS.md. Выполни независимое review текущего diff и коммитов задачи относительно [ветка/коммит базы]. Не меняй файлы. Дай конкретные ошибки и ограничения проверки».
5. Передай найденные проблемы Claude. После исправлений повтори review изменённых мест.
6. После успешной проверки попроси отправить рабочую ветку и создать pull request. Проверь diff PR. Слияние в main публикует изменения, если GitHub Pages настроен на эту ветку: это отдельный осознанный шаг.

## Что значат действия Git

- commit — сохранить проверенную версию локально.
- fetch — получить историю GitHub, не заменяя файлы приложения.
- push рабочей ветки — отправить изменения в отдельную ветку GitHub.
- pull request — показать предлагаемые изменения до включения в main.
- merge в main — включить изменения в основную версию; может запустить публикацию.

## Проверки

- git status --short --branch
- git diff --check
- node --check server.js
- Интерфейс: изменённый сценарий, консоль, мобильная/планшетная/настольная ширина и клавиатура.
- Для расчётов и хранения данных нужны целевые проверки. Синтаксическая проверка не подтверждает правильность расчётов.
- У проекта пока нет npm test. Не сообщать «все тесты прошли» на основании проверки синтаксиса.
- Просмотр интерфейса локально может обращаться к рабочему backend. Не создавать, удалять или редактировать реальные записи во время проверки.
